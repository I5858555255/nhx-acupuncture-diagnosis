# P3-A：受控实验执行协议（草案，BLOCKED_PENDING_AUTHORIZATION）

- 执行日期：2026-10-16（本批执行）
- 执行主体：OpenCode agent（受任务包 §0 授权：P3 处于未授权阶段，本批只草案，不执行任何实验）
- 适用阶段：P3（中期受控实验执行）。
- 授权状态：**`BLOCKED_PENDING_AUTHORIZATION`** —— 本协议为草案，自授权签署后方可启用；在获得用户单独授权之前，不得运行任何候选规则实验（任务包默认授权不含 P3）。
- 依据：任务包 P3 段；五份 P2 方案（M12-2 / 假阳性归因 / 次级信号 recall / 知识条目审计 / 链级归因）均以本协议为执行入口。

---

## 1. 目的

定义 P3 阶段（受控实验执行）的执行流程：在隔离条件下验证 P2 阶段已设计的候选规则方案，并把实验结果登记到正式基线之外，等待用户确认后再合入（HARD-05）。

本协议是草案；启用前须经用户单独授权。

## 2. 准入条件（启用时检查全部满足，否则暂停）

1. P2 方案文档均已完成设计，且各自声明 `BLOCKED_PENDING_AUTHORIZATION` 前已获授权。
2. 隔离执行要求（不修改正式规则、不自动合入结果、完整清理）已在本仓库得知并由执行者遵守（HARD-01、HARD-05、HARD-06）。
3. 正式基线 v14r5 的指标登记（README 第 168 行）保持不变；任何执行脚本不得改写该登记（HARD-03、HARD-01）。
4. 实验设计中引用的全部历史产物均存在且未被破坏（HARD-02）。

## 3. 隔离执行要求

1. **隔离分支/离线副本**：所有实验在本地临时副本创建，不提交、不推送（HARD-05）。
2. **只读对正式基线**：正式 `doubao-acupuncture-diagnosis/`、`canonical_scorer.py` 只读取，任何脚本不得写入（HARD-01、HARD-03）。
3. **不自动合入**：实验产出只写入隔离副本；合入 `main` 需用户显式确认（HARD-05、HARD-06）。
4. **完整清理**：实验结束（成功或失败）后删除临时副本，不遗留新规则版本（HARD-02 之外，避免污染基线目录）。

## 4. 执行流程

1. **初始化隔离工作区**：在本地创建 `tmp_p3_<实验名>/`，复制 v14r5 正式基线与所需历史产物（只读引用）；
2. **应用候选方案**：按对应 P2 方案文档，在隔离副本中实现候选规则变更（候选方案本身由用户确认后提供，或由 P2 设计直接推导但仍须确认）；
3. **复跑评估**：使用 `benchmark_v2/` 下既有的评分与数据构建脚本运行相同数据集；输出到隔离目录；
4. **对照与登记**：汇总指标并与 v14r5 正式基线登记比较；差异必须如实记录，不得调整定义（HARD-03）；
5. **复核**：由执行者独立复核（不依赖同一脚本实现），并留存命令日志与判分明细；
6. **提交候选结果**：生成评审报告并写入隔离目录；不合入 `main`，等待用户决定是否合入门标。

## 5. 结果登记与合入门禁

1. 实验报告一律登记在隔离目录，**不写入 README 的正式指标表**；
2. 合入门标（v14r5 升级为候选基线、新增指标登记）须经用户明确单独授权，且口径差异另开差异报告（任务包规则）。

## 6. 回滚与复核

1. 若候选实验破坏了隔离副本以外的任何文件，立即停止并回滚隔离目录（正式目录不受影响）；
2. 任何异常必须如实写入日志，不得删减或修饰。

## 7. 未授权声明

本协议自启用前必须获得用户单独授权；授权之前任何实验步骤不得启动。授权后启用前，还须完成 §2 准入检查。
